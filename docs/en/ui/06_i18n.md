# Internationalization (i18n)

**Verified sources**: `utils/i18n.py`, `data/i18n/` (observed structure)

> French version: [../../fr/ui/06_i18n.md](../../fr/ui/06_i18n.md)

---

## Architecture

OGMA supports two interface languages: French (`fr`) and English (`en`). The active language is read from `data/settings.json` → key `ui_lang`. Translated strings are in separate JSON files: `data/i18n/ui_fr.json` and `data/i18n/ui_en.json`.

---

## Main API: `t(key)`

The `t(key)` function is the single access point for all interface strings. It:

1. Reads the current language from `settings.json` (without cache to support hot language switching)
2. Loads the corresponding dictionary (with per-language cache)
3. Returns the translation, or the key itself if absent (never an error)

This key fallback behavior guarantees the interface remains readable even if a key is missing from a translation file.

---

## Language switching

`set_lang(lang)` writes the new language into `settings.json["ui_lang"]` without touching other keys. The change takes effect after a page reload (`ui.navigate.reload()`).

`get_lang()` re-reads the file on every call to support this reload without requiring a server restart.

---

## Absolute rule

This module never touches the user's custom instructions (`settings.json["prompts"]`, `persistent_context.txt`). It only manages interface strings.

---

## Adding translations

To add a new translated key:
1. Add the key in `data/i18n/ui_fr.json`
2. Add the same key in `data/i18n/ui_en.json`
3. Use `t('my_new_key')` in the code

If the key is not yet in the JSON files during a test, the interface displays the raw key — intentional behavior for detecting missing keys.
